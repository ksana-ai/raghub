## Evidence boundaries

- Unit and integration tests are local evidence. GitHub Actions is configured,
  but it becomes remote CI evidence only after this revision is pushed and the
  workflow succeeds.
- The readiness probe confirms one local LM Studio endpoint responded with the
  configured model name and vector dimensions. LM Studio did not provide a
  cryptographically verifiable model-weight revision.
- The checked-in benchmark is synthetic. Its results do not establish quality
  on another corpus, production latency, capacity, or availability.
- Caller-supplied tenant and principal headers are not authentication. The API
  must not be exposed directly to untrusted networks.
- No release tag is created by this preparation commit. Tagging
  `v0.1.0-alpha` should follow a successful clean-revision benchmark and green
  remote CI.

## Remaining publication actions

1. Push the accepted commits and require the CI workflow to pass.
2. Enable GitHub private vulnerability reporting and branch protection.
3. Review the GitHub repository description and release notes, then create the

retention, realistic load tests, and deployment hardening remain explicitly
outside this alpha open-source release gate.
